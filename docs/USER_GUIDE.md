# Руководство пользователя

**Программа:** PC HealthCheck  
**Версия:** 1.0.0  
**Платформа:** Windows 10/11 (x64) — основной режим эксплуатации

Документ составлен по структуре ГОСТ 19.505–79 (руководство оператора / пользователя).

---

## 1. Назначение программы

PC HealthCheck предназначена для:

- автоматизированного сбора информации об аппаратной конфигурации и текущем состоянии ПК;
- непрерывного мониторинга телеметрии (температура, загрузка, RAM, GPU, накопители) с отображением на графике;
- диагностики по настраиваемым порогам с выдачей предупреждений и рекомендаций;
- проведения стресс-тестов (CPU, RAM, GPU, диск) и кратких бенчмарков;
- формирования отчётов (TXT, HTML, JSON, MD, CSV) и сравнения снимков «до/после»;
- локального хранения истории измерений в SQLite;
- экспериментальной аналитики с помощью локальной языковой модели (Ollama).

Все данные хранятся **только на компьютере пользователя**; облачная передача телеметрии не выполняется.

## 2. Требования к техническим средствам

| Компонент | Требование |
|-----------|------------|
| ОС | Microsoft Windows 10 или 11, 64-bit |
| Процессор | x64, 2+ ядра (для стресс-тестов — рекомендуется 4+) |
| ОЗУ | не менее 4 ГБ (для RAM-стресса — запас по свободной памяти) |
| Диск | свободное место для БД и отчётов; для дискового стресса — временный файл в `%TEMP%` |
| .NET | **Desktop Runtime 9.x** — только для сборки **framework-dependent** (см. README) |
| AI (опционально) | Установленный и запущенный [Ollama](https://ollama.com), скачанная модель |
| Права | Обычный пользователь; **запуск от администратора** — при отсутствии датчиков WMI/LHM |

## 3. Установка и запуск

### 3.1. Скачивание

1. Откройте страницу **Releases** репозитория на GitHub.
2. Выберите архив:
   - **PC_HealthCheck_win-x64_framework.zip** — если готовы установить [.NET 9 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/9.0);
   - **PC_HealthCheck_win-x64_selfcontained.zip** — если Runtime устанавливать не нужно.
3. Распакуйте архив в папку по вашему выбору.

### 3.2. Установка .NET 9 (только framework-вариант)

Если при запуске появляется сообщение о необходимости .NET:

1. Скачайте **.NET Desktop Runtime 9.x** для Windows x64 с сайта Microsoft.
2. Установите и повторите запуск `PC_HealthCheck.exe`.

### 3.3. Первый запуск

1. Дважды щёлкните по `PC_HealthCheck.exe`.
2. При блокировке SmartScreen: **Подробнее** → **Выполнить в любом случае**.
3. Дождитесь загрузки главного окна (1320×960).
4. При пустых температурах на ноутбуке — закройте приложение и запустите **от имени администратора**.

Данные приложения создаются в:

- `%LocalAppData%\PC HealthCheck\` — база `healthcheck_v2.db`, `settings.json`;
- «Документы» пользователя — файлы отчётов `PCHealthCheck_*.html` и др.

## 4. Описание интерфейса (вкладки)

### 4.1. Дашборд

Сводная панель: модель CPU, объём RAM, температура и загрузка (если доступны), статус в шапке (OK / Warn / Critical). Используйте для быстрой оценки состояния после запуска или смены нагрузки.

### 4.2. Мониторинг

График в реальном времени (собственная отрисовка на Avalonia Canvas, не OxyPlot). Отображаются каналы: температура CPU, загрузка CPU, температура/загрузка GPU, RAM %, температура накопителя, мощность CPU — **в зависимости от доступности датчиков**. На ноутбуках без вентиляторных датчиков включается **адаптивный режим**: как минимум загрузка CPU и RAM. Интервал опроса задаётся в настройках (1–3600 с). Снимки при включённом мониторинге сохраняются в SQLite автоматически.

### 4.3. Утилиты

Просмотр процессов по объёму памяти, сетевых интерфейсов, элементов автозагрузки (Windows — через реестр), очистка временных файлов. Вспомогательные функции для поиска «тяжёлых» процессов и освобождения места.

### 4.4. Диагностика

Анализ текущего снимка: пороги температуры CPU, загрузка RAM, заполнение дисков, признаки SMART, эвристики «узких мест» (CPU/GPU). Результат — список строк с предупреждениями и рекомендациями. Запускается после получения актуального снимка (кнопка **Снимок** в шапке или автоматически при мониторинге).

### 4.5. AI Аналитика

Взаимодействие с локальным сервером Ollama: проверка доступности и модели, ввод вопроса, анализ истории снимков и текущего состояния. Результат: списки аномалий и рекомендаций. Требует отдельной установки Ollama; данные на внешние серверы не отправляются (только localhost).

### 4.6. Тесты

Стресс-тесты и бенчмарки. Профили длительности: 5, 30, 60 минут. Типы нагрузки: CPU, RAM, GPU, диск. **Перед первым стресс-тестом** необходимо принять предупреждение в настройках. GPU на Windows: нагрузка через **Direct3D 11 compute**; при недоступности API в статусе отображается режим **SIMD CPU (GPU API недоступен)** — нагрузка на процессор, не на видеокарту.

### 4.7. Отчёты

Формирование отчёта по текущему снимку (форматы TXT, HTML, JSON, MD, CSV). Сохранение **базового снимка** и построение **сравнительного отчёта** после изменений (апгрейд, настройка, тест). Файлы сохраняются в папку «Документы».

### 4.8. Настройки

Интервал мониторинга, пороги температуры CPU (предупреждение/критический), подтверждение стресс-тестов, светлая/тёмная тема, URL и модель Ollama, комментарий к отчёту. Изменения применяются после сохранения; мониторинг перезапускается с новым интервалом.

### 4.9. Шапка окна

Кнопка **Снимок** — принудительное обновление данных. Индикатор **StatusChip** — обобщённый статус по правилам диагностики.

## 5. Типовые сценарии работы

### 5.1. Снимок → Диагностика → отчёт HTML

1. Запустите приложение, дождитесь первого снимка или нажмите **Снимок**.
2. Перейдите на вкладку **Диагностика**, выполните анализ.
3. Откройте **Отчёты**, выберите формат **HTML**, сформируйте отчёт.
4. Откройте файл из «Документов» в браузере.

### 5.2. Мониторинг 5 минут

1. В **Настройках** установите интервал, например 5 с.
2. Включите мониторинг (при старте он активен по умолчанию после инициализации).
3. Наблюдайте график на вкладке **Мониторинг** не менее 5 минут.
4. Убедитесь, что файл `%LocalAppData%\PC HealthCheck\healthcheck_v2.db` увеличился в размере.

### 5.3. Стресс CPU

1. В **Настройках** включите подтверждение риска стресс-тестов.
2. Закройте ресурсоёмкие приложения.
3. На вкладке **Тесты** выберите короткий профиль (5 мин) и запустите **CPU**.
4. Следите за прогрессом и температурой; при необходимости нажмите **Стоп**.
5. По завершении проверьте статус «Тест завершен успешно»; результат записан в БД.

### 5.4. Стресс GPU (Windows)

1. Выполните шаги подтверждения из п. 5.3.
2. Запустите тест **GPU**.
3. В статусе должно быть указание режима **D3D11** (дискретная или встроенная GPU).
4. Если отображается **SIMD CPU** — видеодрайвер или D3D11 недоступны; тест не нагружает GPU.
5. При температуре GPU ≥ 95 °C тест может остановиться автоматически.

## 6. Сообщения об ошибках и действия пользователя

| Ситуация | Действие пользователя |
|----------|------------------------|
| Сообщение о необходимости **.NET 9** / Runtime | Установить Desktop Runtime 9.x или скачать **selfcontained** zip |
| **Нет температуры CPU** | Допустимо на части ноутбуков; ориентируйтесь на загрузку CPU %; запуск от администратора |
| **Ollama недоступен** | `winget install Ollama.Ollama`, `ollama pull llama3.2`, проверка на вкладке AI |
| **Ошибка записи в БД** | Не удалять `healthcheck_v2.db` при работе программы; проверить права на `%LocalAppData%\PC HealthCheck\` |
| **Стресс не запускается** | Включить подтверждение в настройках; убедиться, что другой тест не выполняется |
| **SmartScreen блокирует exe** | Подробнее → Выполнить; для production — кодовая подпись издателя |
| **График пустой** | Подождать 1–2 интервала опроса; на ноутбуке без датчиков смотреть CPU % и RAM % |

## 7. Меры безопасности

- Стресс-тесты выполняются **только после явного подтверждения** в настройках.
- При превышении критического порога температуры **CPU** стресс-тест останавливается автоматически.
- При GPU-стрессе и температуре GPU **≥ 95 °C** тест останавливается автоматически.
- Дисковый стресс создаёт временный файл в `%TEMP%` и удаляет его по завершении.
- Не оставляйте стресс-тест без присмотра на слабой системе охлаждения.
- Отчёты и БД **не шифруются** по умолчанию; храните их с учётом локальной политики безопасности.

## 8. Контрольный пример (10–15 минут)

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Запуск `PC_HealthCheck.exe` | Окно открыто, шапка с кнопкой «Снимок» |
| 2 | Нажать **Снимок** | Заполнены сведения о CPU/RAM на Дашборде |
| 3 | **Диагностика** → анализ | Список строк (температура, RAM, диски) |

| 5 | **Мониторинг**, интервал 5 с, подождать 5 мин | График с точками CPU % / RAM % (минимум) |
| 6 | **Настройки** → подтвердить стресс | Флажок принятия риска включён |
| 7 | **Тесты** → CPU, профиль 5 мин | Прогресс 0–100 %, статус «завершен» |
| 8 | Проверить `%LocalAppData%\PC HealthCheck\` | `healthcheck_v2.db` существует |

## 9. Аварийные ситуации

- **Перегрев во время теста** — нажмите **Стоп**; дождитесь снижения температуры; проверьте пыль/термопасту/профиль вентиляторов.
- **Зависание интерфейса** — завершите процесс через диспетчер задач; при следующем запуске SQLite (режим WAL) сохранит ранее записанные снимки.
- **Повреждение БД** — переименуйте `healthcheck_v2.db`; приложение создаст новую при следующем запуске (история будет потеряна).
